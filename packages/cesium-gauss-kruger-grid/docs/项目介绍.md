# Cesium 高斯—克吕格方里网：项目介绍

本文面向第一次接触这套代码的使用者，说明它解决什么问题、怎样运行、各个配置表示什么。算法与绘制实现见[架构设计](./架构设计.md)，完整导出入口见 [src/index.ts](../src/index.ts)。

本文中指向 `../../../src/`、`../../../scripts/` 的相对链接仅在完整源码仓库中可用。发布包包含本包的 `src/`、`docs/`、`skills/` 学习与维护资料，以及 `dist/` 构建产物和 README；根项目的 Vue 示例、测试脚本与测试页面不随本包发布。

## 1. 项目做什么

`cesium-gauss-kruger-grid` 在 Cesium 三维地球上显示高斯—克吕格投影坐标网。它先在平面坐标系中生成“东坐标不变”或“北坐标不变”的线，再反投影到地球，绘制线段及屏幕边缘坐标。

它适合学习地图投影、在三维业务地图中提供投影坐标参考，以及在固定测区显示一公里间隔的坐标网。它不依赖 Vue；Vue 只用于本仓库的演示页面。图层接收已经存在的 `Cesium.Scene`，自身不创建 Viewer，也不访问底图、地形或坐标转换服务。

“方里网”与“经纬网”需要分清：经纬网按角度划分，方里网按投影平面的米划分。`gridSpacing: 1000` 表示平面上相邻坐标线相隔 1,000 m；投影存在尺度变形，地表实际距离并非处处等于 1,000 m。高斯—克吕格属于横轴墨卡托投影，其参数与尺度性质可参考 [PROJ 官方说明](https://proj.org/en/stable/operations/projections/tmerc.html)。

## 2. 功能与边界

| 能力       | 当前实现                                                                             |
| ---------- | ------------------------------------------------------------------------------------ |
| 投影分带   | 3° 或 6°；随视域自动分带，也可固定一个带号                                           |
| 固定格网   | `bounded` 模式，保持指定米制格距；低空超预算时尝试保留相机附近格网，高空超预算仍隐藏 |
| 自适应格网 | `lod` 模式，依据相机高度与投影范围选择真实的更粗格距                                 |
| 坐标标签   | 左侧和下侧边缘显示坐标；旋转时交换坐标轴边缘，进行避让                               |
| 三维绘制   | 实例化三角形组成线段，保持屏幕像素宽度，支持主线和普通线                             |
| 更新与清理 | 自动跟随相机和画布变化，兼容按需渲染，拥有独立销毁流程                               |
| 调试状态   | 暴露带号、中央经线、实际格距、折线片段数和线段数                                     |

使用前需要明确以下范围：

- 仅支持 `SCENE3D` 和 WGS84 场景椭球；2D、Columbus View 和模式切换过程中隐藏，回到 3D 后重建。
- 当前可绘制纬度为 80°S～84°N，这是实现选择，不是投影公式的全球适用性声明。
- 线绘制在椭球上方，未采样地形，也不贴地。地形和模型可能遮挡线段。
- 投影输入按 CGCS2000/GRS80 地理坐标解释，显示采用同一经纬度的 WGS84 位置。代码没有实现基准、历元或控制网转换。
- 中国境外沿用周期带号属于数学扩展，不代表注册的境外 CGCS2000 测绘坐标参考系。
- LOD 间距可以大于或小于一公里。只有固定 `gridSpacing: 1000` 才能持续保持一公里的投影格距。
- 屏幕标签用于交互阅读，当前没有完整纸质地形图图式、地图分幅、邻带坐标短线或测绘成果输出功能。

## 4. 先理解坐标和单位

同一个点在流程中会经历以下几种表示：

| 表示                    | 示例/单位                               | 用途                             |
| ----------------------- | --------------------------------------- | -------------------------------- |
| 地理坐标 `Cartographic` | 经度、纬度为弧度，高度为米              | Cesium 与包的地理输入输出        |
| Proj4js 地理数组        | `[经度°, 纬度°]`                        | 投影转换器内部边界               |
| 平面坐标                | `{ easting, northing }`，米             | 生成规则格网；东坐标不含带号前缀 |
| 地心坐标 ECEF           | `Cartesian3(x, y, z)`，米               | 在三维场景中绘制线段             |
| 屏幕坐标                | CSS 像素；Canvas/GPU 还换算实际像素倍率 | 线宽、标签位置和避让             |

包负责 `Cartographic` 的弧度与 Proj4js 的角度转换。Proj4js 默认顺序是 `[longitude, latitude]` 和 `[easting, northing]`，可见 [Proj4js 官方 API](https://proj4js.org/)。不要将中文测绘习惯的 X/Y 名称直接当成数组顺序。

本实现的投影参数为 GRS80 椭球、赤道原点、中央经线比例因子 `1`、假东偏 `500000 m`、假北偏 `0 m`。中央经线计算如下，其中 `z` 是带号：

```text
6° 分带：中央经线 = 6 × z − 3 度
3° 分带：中央经线 = 3 × z 度
```

6° 第 20 带和 3° 第 39 带均以 117°E 为中央经线。全球周期编号使用 6° 带 `1～60`、3° 带 `0～119`，3° 的 0 带跨越 Greenwich。带界的 ±180° 和浮点误差在投影模块中统一处理。

屏幕格式按 X 为北坐标、Y 为含带号的东坐标：

```text
X = northing / 1000                         单位 km
Y = (zoneNumber × 1000000 + easting) / 1000   单位 km
```

例如 `zoneNumber=20, easting=500000` 对应完整文本 `Y 20500 km`。屏幕 Canvas 将高位数字缩小、公里末两位放大；页面说明轴与单位，而 `formatGridCoordinate()` 返回包含 X/Y 和 km 的完整字符串。带号只在格式化时加入，不能把 `20500000` 直接作为带内东坐标传给 `unproject()`。

## 5. 两种使用方式

### 5.1 固定一公里格网

应用先创建 Viewer，再将其 `scene` 传给图层。在本仓库新增示例时，必须采用共享的 `createLocalWorldBaseLayers` 底图，并在 Viewer 创建后立即调用 `applyDefaultViewerConfig`；完整初始化可直接参考[现有示例](../../../src/examples/primitive/square-kilometer-grid/index.vue)。

```ts
import { GaussKrugerGrid } from "cesium-gauss-kruger-grid";

// viewer 为应用已经创建且尚未销毁的 Cesium.Viewer。
const grid = new GaussKrugerGrid(viewer.scene, {
  calculationMode: "bounded",
  zoneWidthDegrees: 6,
  zoneNumber: 20, // 固定 20 带；省略表示视域自动分带
  gridSpacing: 1000, // 始终保持 1,000 m 格距
  maximumLinesPerAxis: 64,
  altitude: 20,
});

// 初始 refresh 已在构造中完成，所以先读取当前状态。
console.log(grid.status);
const removeChanged = grid.changed.addEventListener((status) => {
  console.log(status);
});

// 卸载图层或页面时：先取消调用方监听，再销毁图层。
// 以下代码应放在实际卸载回调中，而非紧接构造立即执行。
function disposeGrid(): void {
  removeChanged();
  grid.destroy();
}
```

`bounded` 会用投影范围估计线数，正常情况下保持原本带余量的可见范围。低空倾斜时，地平线可能把经纬度包围框拉得很大；超出预算后，若相机椭球高度不大于 `gridSpacing × (maximumLinesPerAxis − 1) / 2`，会尝试只生成相机地表位置附近的局部格网。上述例子对应的高度门槛为 31,500 m，它是启动回退的条件，不是绘制半径。

局部经纬窗口与原视域求交后，按实际分带后的投影跨度最多进行 4 轮预算校验，必要时收缩；固定格距不变，远处不再生成。窗口不是精确视锥边界或圆形距离范围。相机升到门槛以上且全视域超预算、局部范围无效，或后续候选线/采样点仍超预算时，格网仍会隐藏。它不会自动将 1 km 改为 5 km。

回退用视锥四角射线与相机地表切平面的关系排除确定全部朝天的视锥，不依赖屏幕中心命中地球。因此中心朝天、屏幕下沿仍包含地面的视角可以继续尝试生成局部格网。

### 5.2 自适应浏览

```ts
import { GaussKrugerGrid } from "cesium-gauss-kruger-grid";

const grid = new GaussKrugerGrid(viewer.scene, {
  calculationMode: "lod",
  zoneWidthDegrees: 6,
  maximumLinesPerAxis: 12,
  maximumEastingSpacing: 500000,
});
```

LOD 先依据相机高度选择层级，再检查投影跨度是否需要更粗层级。`maximumLinesPerAxis` 是选层目标，不是最终线片段数的严格上限；分带、裁切、多次进入视域，以及东坐标间距上限都会影响最终数量。北坐标和东坐标的实际间距应分别读取 `northingGridSpacing` 与 `eastingGridSpacing`。

可选 `spacingLevels` 必须满足高度上限严格递增、间距正且不递减。若希望近景仍以一公里为最小格距，可参考示例自定义层级；库的内置层级会细化到 100 m。

### 5.3 显示、刷新与状态

```ts
grid.show = false; // 隐藏几何和标签，暂停后续自动更新
grid.show = true; // 依据当前相机状态重新生成
grid.refresh(); // 必要时手动重建；通常自动更新即可
```

构造参数会被解析并复制，其中 `Color` 与层级数组也会复制。修改调用方原来的 `options` 不会更新图层；当前没有公开的 `setOptions()`。示例切换模式时会解除旧监听、销毁旧图层，再以新参数创建实例。

`status.rangeLimited === true` 表示本次固定模式采用低空局部范围，格距不变，但不覆盖整个远方视野。正常全视域与 LOD 结果为 `false`；LOD 的选层策略没有因这项回退而改变。

`status === undefined` 表示本次构建无法建立有效格网范围或主动清除了状态，例如视域不存在、固定带不相交、场景模式不支持、高空超预算，或局部回退后仍不能满足预算。它不等价于所有“屏幕无可见线”的情况：范围建立成功但没有整格距坐标线、或采样后没有可见片段时，仍可能返回有状态的零线结果。应同时检查 `segmentCount`、`drawCommandCount` 和图层 `show`。隐藏图层也不会自动抹掉之前的 `status`。

## 6. 库默认值与示例覆盖值

理解“代码默认”和“页面当前配置”的区别，有助于解释为什么直接调用包时效果与演示不同。

| 参数                              | 包默认                                  | 示例固定模式 | 示例 LOD 模式  |
| --------------------------------- | --------------------------------------- | ------------ | -------------- |
| `calculationMode`                 | 提供 `gridSpacing` 时 bounded，否则 lod | bounded      | lod            |
| `zoneWidthDegrees` / `zoneNumber` | 6° / 自动                               | 6° / 自动    | 6° / 自动      |
| `gridSpacing`                     | 1,000 m，仅 bounded 使用                | 1,000 m      | 不使用         |
| `spacingLevels`                   | 100 m～2,000 km                         | 不使用       | 1 km～2,000 km |
| `maximumLinesPerAxis`             | 28                                      | 64           | 12             |
| `maximumEastingSpacing`           | 500,000 m                               | 不使用       | 500,000 m      |
| `altitude`                        | 100 m                                   | 20 m         | 20 m           |
| `majorLineWidth`                  | 2.5 px                                  | 1.75 px      | 1.75 px        |
| `minimumLabelSpacing`             | 72 px                                   | 72 px        | 48 px          |

以下参数示例与库默认相同：

| 参数                                                  | 值及意义                                                      |
| ----------------------------------------------------- | ------------------------------------------------------------- |
| `viewPadding`                                         | 0.12；可见经纬度跨度外扩比例                                  |
| `sampleSpacing`                                       | 自动；显式设置时为投影采样步长上限，单位米                    |
| `lineColor`                                           | 白色，alpha=0.82                                              |
| `lineWidth` / `majorLineEvery`                        | 普通线 1.25 CSS px / 每 10 个格距一条主线                     |
| `labelPixelRatio`                                     | 2；最终 Canvas 倍率不低于设备倍率和此值中的较大者，但上限为 4 |
| `refreshInterval` / `labelUpdateInterval`             | 80 ms / 32 ms                                                 |
| `largeViewRefreshInterval` / `largeViewZoneThreshold` | 250 ms / 4 个投影带                                           |

示例初始相机位于 117°E、39.907°N 上空 10,000 m，朝向地面，默认开启固定模式。它是展示配置，不是类的固定相机行为。

## 7. 安装、构建和验证

在当前源码仓库使用 pnpm workspace，根项目的依赖写为 `cesium-gauss-kruger-grid: workspace:*`。以下根项目命令和回归页面需要完整仓库，单独安装 tgz 不会附带它们。从仓库根目录执行：

```sh
pnpm install
pnpm test:gauss-kruger-grid
pnpm build
pnpm dev
```

`test:gauss-kruger-grid` 先构建包，再运行投影和几何 Node 检查。`pnpm build` 构建工作区依赖包、执行 `vue-tsc`，然后生成应用生产包。开发服务启动后打开：

- `/examples/primitive/square-kilometer-grid`：交互示例。
- `/scripts/grid-regression.html`：真实浏览器和 WebGL 回归页面。

手动检查模式切换、缩放、旋转、跨带、反经线、视场角变化、标签和导航卸载，确认浏览器控制台没有新增错误。单独构建与打包可执行：

```sh
pnpm --filter cesium-gauss-kruger-grid build
pnpm --dir packages/cesium-gauss-kruger-grid pack --pack-destination artifacts
```

`prepack` 会先构建。产物是 ESM、类型声明和 source map，GLSL 由 Vite 内联；使用方不需要另配 GLSL loader。Cesium 和 proj4 保持外部依赖，前者是 peer dependency，后者是直接依赖。包没有提供 CommonJS 入口。

独立项目可安装生成的 tgz 与 Cesium：

```sh
pnpm add <实际生成的tgz路径> cesium@~1.143.0
```

要保留目标应用的 lockfile。已验证组合为 `cesium@1.143.0`、`@cesium/engine@26.1.0`、`@cesium/widgets@16.1.0`。此前独立安装检查中，Cesium 1.143.0 的宽泛间接依赖曾解析到 engine 26.4.0，导致 Cesium ESM 入口找不到 `_shadersPolygonSignedDistanceFS` 导出；这是依赖组合问题。新建 pnpm 项目可在应用自己的 `pnpm-workspace.yaml` 中锁定：

```yaml
packages:
  - .
overrides:
  "@cesium/engine": 26.1.0
  "@cesium/widgets": 16.1.0
```

本仓库已有锁定依赖，不必为这一步改写现有版本。包使用了 Cesium 内部渲染接口，peer 限制为已验证的 `1.143.x`；升级应重新运行浏览器着色器、按需渲染和资源释放回归。
