# 已有对象的 LOD 显隐管理

`LodManager` 只调度已有表现对象，不创建 Entity，不接管 Scene，也不改变各表现
的绘制方式。`asLodView()` 可以接入具有 `show` 的 Model、Billboard 和独立
Primitive。批量渲染器中的单个实例应自行适配 `LodView.setVisible()`，不要修改
整批 Primitive 的 `show`。

每个目标只调用一次 `add()`。移动目标支持两种位置来源，二选一：

- `position`：注册时复制坐标，之后用 `setPosition(id, position)` 更新，内部
  复用坐标缓存。
- `getPosition`：距离判断时每轮读取；可以返回持续原地更新的同一个
  `Cartesian3`，管理器按数值快照检测变化。

在业务插值及渲染对象位置更新后调用一次：

```ts
lod.update(camera.positionWC, camera.positionCartographic.height);
```

位置必须是与渲染对象一致的世界坐标。相机高度是相对椭球的高度；地形离地高度
需调用方另行计算并传入。管理器不更新模型矩阵或 billboard 位置。

层级按距离或高度的 `[min, max)` 半开区间配置，必须按 `min` 递增且不能重叠，
允许间隙和 `Infinity`。未匹配的范围隐藏所有表现。初次选择直接匹配区间；后续
当前区间向两侧扩展 `hysteresis` 米，包括隐藏区间。例如 `[0, 100)`、滞回
10 米，退出需达到 110 米，隐藏后重新显示需小于 90 米。跨越多个区间时一次
跳到实际对应的层级，不逐级过渡。

滞回值不会自动裁剪，应远小于层级和间隙的宽度。距离模式还需确保最远有限
上界减去滞回值仍大于零，否则远端隐藏区会覆盖全部非负距离，隐藏后无法靠
接近目标重新显示。高度模式也应让每个期望恢复的阈值处于实际相机可达范围。

`setMetric()` 切换指标时重置滞回状态；`setEnabled()` 控制业务总开关。这些设置
与 `setPosition()` 一样在下一次 `update()` 统一应用。`update()` 仅在显隐变化
时返回 `true`，未切换层级不会重复写入 `.show`。开启 `requestRenderMode` 时，
业务修改后需请求渲染以驱动更新，并在返回 `true` 时请求显示最新结果。

`add()` 立即隐藏所有表现，首次 `update()` 再选择显示对象。`getLevel(id)` 返回
注册的 `levels` 数组下标，全部隐藏时为 `-1`。每个表现只能由一个目标管理，
其他逻辑应通过管理器设置总开关，避免同时竞争显隐。

对象所有权属于调用方。`remove()` / `destroy()` 立即隐藏当前表现，但不会销毁
对象、释放纹理或移除场景 Primitive。调用方应先销毁管理器，再释放渲染资源。
该管理器不会把独立模型自动合并为实例化批次，也不会隐藏时卸载模型。

验证：`node scripts/lod-manager-check.mjs`。脚本执行实际管理器和 Cesium 坐标
代码，检查移动目标、模式切换、滞回、远跳、隐藏间隙、显隐写入及资源所有权。
