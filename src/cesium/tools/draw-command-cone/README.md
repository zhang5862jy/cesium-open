# 批量圆锥更新

保留单个 DrawCommand、共享 RenderState、三种材质及原来的完整列表接口：

```ts
primitive.setInstances(instances);
```

现在按数值快照比较输入：相同数据不重新打包或上传；仅改颜色、材质类型、
速度或段数时跳过方向归一化、四元数及包围球计算。修改输入对象后仍需要调用
更新方法，不依赖对象引用是否变化。

只更新少量目标时可以传入现有列表中的连续区间：

```ts
instances[500].animationSpeed = 2;
primitive.updateInstances(500, [instances[500]]);
```

此接口不改变列表长度；新增、删除、排序继续使用 `setInstances()`。多次调用
在下一帧合并上传，相邻脏槽位合并；脏实例超过半批或 64 个时整批上传以限制
WebGL 调用数量。输入先完整校验，再修改内部数据。

几何更新缓存每个圆锥的包围球，下一帧仅合并一次整批包围球；纯材质更新不
触发合并。包围球计算仍为 O(N)，没有宣称单个移动目标的全部更新都是 O(1)。
额外 CPU 快照及包围球缓存为每个容量槽位 160 字节。

着色器将逐实例常量标记为 `flat`，动态材质端盖提前丢弃，波纹间隙及渐变
透明片元跳过光照。网格分段数、透明混合、深度状态及绘制 Pass 保持原配置。
因此大量重叠透明圆锥的像素填充成本仍存在。

## 验证

运行 `pnpm dev`，打开 `/scripts/cone-regression.html`：真实 WebGL 验证重复提交、
局部上传偏移、相邻范围合并、无效输入原子性、缩容、清空重建、包围球、隐藏
恢复和资源释放。

本机浏览器 1000 个实例、每组 200 次调用、7 组中位数的 CPU 对比：

| 情况 | 修改前 | 修改后 |
| --- | --- | --- |
| 完整提交相同数据 | 0.271 ms/次 | 0.043 ms/次 |
| 改一个材质（旧完整提交 → 新局部接口） | 0.267 ms/次 | 约 0.001 ms/次 |
| 单实例 GPU 上传 | 80,000 字节 | 80 字节 |

时间为当前环境的 CPU 提交测量，不包含 GPU 完成时间；不能当作整体 FPS 提升。
原、新实现的实例缓冲数值逐项对比一致。
